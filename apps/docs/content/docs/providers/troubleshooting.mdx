## "No API key"

1. Open **Settings → API keys** and paste the provider's key, then press **Test**.
2. On a server, check the variable name: RootClaw reads the `ROOTCLAW_` names listed in [Model providers](./index.mdx#built-in-providers). An unprefixed `OLLAMA_API_KEY` or `ANTHROPIC_API_KEY` is only a driver fallback and does not show as configured.
3. A variable in the server's environment wins over a saved key. Restart the server after changing its environment.

Keys you export in your shell (`~/.zshrc`, `~/.bashrc`) don't reach the desktop app when you open it from the Dock, Finder or an app menu. Save the key in Settings instead.

## Authentication failures

A `401 Unauthorized` means the provider rejected the key. Check it was copied whole, belongs to the provider you picked, and has not been revoked; then save it again (on a server, `rootclaw engine set KIND --key-env VAR --rotate`).

## A selected model fails

- Refresh the provider's models in the model picker.
- Choose a model actually available to that provider account.
- For an OpenAI-compatible service, confirm the base URL ends where the service expects (usually `/v1`) and that the model supports tools; set `config.tools` to `false` for one that does not.

## "Provider instance is unavailable"

The bot's model belonged to a removed engine (Claude Code, Codex, an ACP agent, OpenCode and the like). Open the bot's settings and choose a model on a configured provider.
